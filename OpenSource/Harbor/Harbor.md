# Harbor (Docker Compose, online installer)

Self-hosted [Harbor](https://goharbor.io/) container registry, installed with
Harbor's **official online installer** (`install.sh` + `prepare`, run
unmodified) behind a host Nginx reverse proxy. Nginx terminates TLS on 80/443;
Harbor's own Nginx speaks plain HTTP on `127.0.0.1:<port>` only. This is the
topology Harbor documents for running behind a TLS-terminating proxy: the
`https:` block commented out and `external_url` set.

## Layout

```
Harbor/
├── Harbor.md
├── harbor-nginx.conf              # Reverse proxy template (placeholders: harbor.example.com, 127.0.0.1:8095)
└── scripts/
    ├── harbor-docker-install.sh   # Downloads + verifies the online installer, writes harbor.yml, runs install.sh, wires up Nginx/certbot
    ├── harbor-docker-backup.sh    # pg_dump + secret keys + image storage + harbor.yml, timestamped
    └── harbor-docker-restore.sh   # Restores a snapshot into a running instance
```

The installed instance lives at `/var/www/docker/harbor/<domain>/`:

| Path                          | Contents                                                              |
|-------------------------------|------------------------------------------------------------------------|
| `harbor/`                     | The official online installer, extracted                              |
| `harbor/harbor.yml`           | **Written by the installer** (mode `600`) — the one config file        |
| `harbor/docker-compose.yml`   | Generated by `./prepare` from `harbor.yml` — never edit it             |
| `harbor/common/config/`       | Generated by `./prepare` (root-owned env files)                        |
| `data/`                       | `data_volume`: `database/`, `registry/` (images), `secret/`, `redis/`, `job_logs/`, `trivy-adapter/` |
| `logs/`                       | `log.local.location`: one log file per component (`core.log`, `registry.log`, …) |

> [!important]
> **One Harbor per Docker host.** Harbor's compose file hard-codes its container
> names (`nginx`, `redis`, `registry`, `registryctl`, `harbor-core`, `harbor-db`,
> `harbor-log`, `harbor-portal`, `harbor-jobservice`, `trivy-adapter`), its
> log collector always takes `127.0.0.1:1514`, and every instance's Compose
> project is called `harbor` (the folder name). A second `install.sh` would
> start with `docker compose down -v` on the **first** instance's project. The
> install script refuses before touching anything if any of those exist.
>
> The backup and restore scripts find the instance with
> `find /var/www/docker/harbor -path '*/harbor/harbor.yml'` and talk to the
> containers by those fixed names.

## Prerequisites

- Docker 20.10.10+ and the Docker Compose plugin; your user in the `docker`
  group, plus `sudo`
- Network access to GitHub (installer download) and Docker Hub (images)
- Nginx and certbot on the host
- A public DNS record for the domain — Harbor issues registry tokens and push
  URLs against it, so it must be the name clients use
- `127.0.0.1:1514` free (Harbor's log collector)
- Optional but recommended: **cosign v2.5+** (v2.4 also works) to verify the
  installer's signature. Without it the script asks before continuing unverified.

  ```bash
  curl -LO https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64
  sudo install -m 755 cosign-linux-amd64 /usr/local/bin/cosign && rm cosign-linux-amd64
  ```

## Install

```bash
./scripts/harbor-docker-install.sh
```

You'll be prompted for:

- **Domain** — e.g. `harbor.example.com`
- **Port** — host port on `127.0.0.1` (default `8095`). The same value goes into
  `harbor.yml` and the Nginx vhost. If something already listens on it, the
  script shows what and asks.
- **Version** — defaults to the latest GitHub release; `v2.15.0` or newer
- **Trivy** — the vulnerability scanner, `install.sh --with-trivy` (default yes)
- **Admin password** — blank generates one. Harbor's policy applies: 8–128
  characters, one uppercase, one lowercase, one digit.
- **Database password** — blank generates one

Passwords are limited to `A-Z a-z 0-9 . _ ~ -`. They end up in YAML, in the env
files `prepare` generates (Compose expands `$` there) and in the SQL that sets
the database password, and those characters need no escaping in any of them.

### What the script does

1. Refuses if Harbor's container names, `127.0.0.1:1514`, or another instance
   directory already exist, or if the instance directory isn't empty
2. Downloads `harbor-online-installer-<version>.tgz` from the GitHub release and,
   with cosign, verifies it exactly as
   [Harbor's signature guide](https://github.com/goharbor/harbor/blob/main/docs/signature-verification.md)
   documents (`--new-bundle-format` is added for cosign 2.4.x, which needs it)
3. Extracts it to `/var/www/docker/harbor/<domain>/harbor/`
4. Writes `harbor.yml` from `harbor.yml.tmpl`, changing only the lines below. Each
   is an exact whole-line match, so a changed template stops the script.
5. Offers to open `harbor.yml` in `$EDITOR`
6. Runs `sudo ./install.sh [--with-trivy]` unmodified: `prepare` renders the
   config, then Compose pulls the images and starts Harbor
7. Checks Harbor's proxy is published on `127.0.0.1:<port>`, then polls
   `/api/v2.0/ping` until it answers `Pong`
8. Optionally runs certbot and installs the Nginx vhost (same prompts as the other apps)

### `harbor.yml` — what changes from the template

| Setting                 | Template                     | Written                     |
|-------------------------|------------------------------|-----------------------------|
| `hostname`              | `reg.mydomain.com`           | `<domain>`                  |
| `http.port`             | `80`                         | `"127.0.0.1:<port>"`        |
| `https:` block          | enabled                      | commented out               |
| `external_url`          | commented out                | `https://<domain>`          |
| `harbor_admin_password` | `Harbor12345`                | asked / generated           |
| `database.password`     | `root123`                    | asked / generated           |
| `data_volume`           | `/data`                      | `<instance>/data`           |
| `log.local.location`    | `/var/log/harbor`            | `<instance>/logs`           |

Everything else is Harbor's default.

**Why `http.port` holds an address.** `prepare` copies `http.port` verbatim
into the proxy service's port mapping (`{{http_port}}:8080`), so
`"127.0.0.1:8095"` becomes `127.0.0.1:8095:8080`. Because it lives in
`harbor.yml`, it survives every later `./prepare` and `migrate`. Editing the
generated `docker-compose.yml` instead would be silently reverted by the next
`./prepare`, putting Harbor back on `0.0.0.0`, where Docker-published ports
bypass ufw. Keep this value when you edit `harbor.yml`.

`harbor_admin_password` is only used on the very first start. After that the
admin account lives in the database; change its password in the UI.

## Using the registry

```bash
docker login harbor.example.com
docker tag myapp:1.0 harbor.example.com/library/myapp:1.0
docker push harbor.example.com/library/myapp:1.0
```

`library` is the default public project. Create private projects in the UI,
and use **robot accounts** (project → Robot Accounts) for CI rather than a
personal login.

## Nginx reverse proxy

`harbor-nginx.conf` is installed to `/etc/nginx/sites-available/<domain>` with
the domain and port substituted. What matters in it for a registry:

- `client_max_body_size 0` — layers can be gigabytes. Without it pushes fail with 413.
- `proxy_request_buffering off` / `proxy_buffering off` — stream layers through
  instead of spooling them to disk. These are the settings Harbor's own Nginx uses.
- `X-Forwarded-Proto $scheme` — Harbor's Nginx passes it on to core and the
  registry. Without it they hand clients `http://` URLs.
- `Host $http_host` — the registry builds the token realm
  (`https://<domain>/service/token`) from the request's host.
- Long timeouts (900s) for big pushes and pulls, plus HSTS, which Harbor only
  sends itself in its own HTTPS mode.

## Reconfigure

`harbor.yml` is the only file you edit. Apply a change the way Harbor documents:

```bash
cd /var/www/docker/harbor/<domain>/harbor
sudo docker compose down
$EDITOR harbor.yml
sudo ./prepare --with-trivy      # leave out --with-trivy if Trivy is disabled
sudo docker compose up -d
```

- Pass `--with-trivy` every time if Trivy is enabled. Without it, `prepare`
  drops Trivy from the generated compose file.
- `sudo` is needed for every `docker compose` command here, because `prepare`
  writes Harbor's env files readable by root only.
- Never edit `docker-compose.yml` or `common/config/` — `prepare` overwrites them.

## Backup

```bash
./scripts/harbor-docker-backup.sh
```

You pick the backup root (default `/home/backup`) and whether to include the
image storage. Each run makes one snapshot:

```
/home/backup/harbor/<domain>/<YYYY-MM-DD-HH-MM-SS>/
├── postgres/registry.sql.gz   # pg_dump of "registry", Harbor's only database
├── secret/secret.tar.gz       # data/secret: keys/secretkey + token-signing keys
├── registry/registry.tar      # data/registry: layers and manifests (optional)
├── config/harbor.yml          # reference copy (mode 600)
└── manifest.txt               # Harbor version, images, sizes
```

- **Harbor stays up.** `pg_dump` reads a consistent snapshot. The image storage is
  archived *after* the dump, so a push in between leaves an unreferenced blob
  (removed by garbage collection), never a database row pointing at a missing
  layer. **Don't run garbage collection during a backup.**
- **`secretkey` is not optional.** Harbor encrypts the credentials it stores in the
  database with it (replication endpoints, OIDC client secret, …). A database
  restored without its key loads, but those secrets can't be decrypted.
- **`registry.tar` is uncompressed**, because layers are gzip already. It is
  about the size of `data/registry`. The script shows the size and checks free space first.
- **What's not archived:** Redis (cache, sessions, job queue), `job_logs`, the
  Trivy DB cache (downloaded again), `logs/`, the generated compose and
  `common/config` (`prepare` regenerates them), Nginx and certificates.
- **Retention:** the last 7 snapshots per domain are kept.
- **No sudo:** data is read through a throwaway `busybox` container, as the Plane
  scripts do.

## Restore

```bash
./scripts/harbor-docker-restore.sh
```

Restores into an instance that is **installed and running**. Pick the snapshot:

```
  #    Date                         Version   Database  Secrets  Images     Note
  ---- ---------------------------- --------- --------- -------- ---------- ----
  1)   October 9, 2026, 05:23 PM    v2.15.4   ok        ok       --         pre-restore
  2)   October 9, 2026, 05:22 PM    v2.15.4   ok        ok       301M
```

Then pick what to restore:

1. **Full restore** — database + secret keys + image storage. Use it for disaster
   recovery or a full rollback.
2. **Database + secret keys only** — keeps the target's image storage. Use it to
   roll back projects, users and settings on the same host. Layers removed by
   garbage collection since the snapshot are gone.

The database and the secret keys always go together.

What happens:

1. **Safety snapshot (optional, default yes).** The target's current database,
   keys and `harbor.yml` (not its images) are saved first, in the normal snapshot
   format. Undo the restore by restoring that snapshot with option 2.
2. Everything except `log`, `postgresql` and `redis` is stopped
   (`sudo docker compose stop`).
3. The `registry` database is dropped, recreated and loaded in a single transaction.
4. `data/secret` is replaced, keeping owner `10000` and mode `600`.
5. For a full restore, `data/registry` is emptied and extracted.
6. Redis is flushed. The registry caches layer info there, and a stale entry
   would claim a layer exists that the restored storage doesn't have.
7. `sudo docker compose up -d`, then a wait for `/api/v2.0/ping`.

- **`harbor.yml` is not touched.** The target keeps its own domain, port and
  paths, so a snapshot can go into an instance with another domain.
- **Version rule:** the target must run the snapshot's Harbor version or newer.
  harbor-core migrates an older schema on start, as in an upgrade (so the
  snapshot must be within Harbor's supported upgrade range), but nothing can
  go backwards. The script refuses a newer snapshot.
- **Logins come from the snapshot,** including the admin password. Everyone has
  to log in again.

**Disaster recovery onto a new host:**

```bash
./scripts/harbor-docker-install.sh     # same domain, snapshot's version or newer
./scripts/harbor-docker-restore.sh     # option 1 - full restore
```

## Upgrading

Harbor's documented upgrade procedure, adapted to this layout. Read the
[release notes](https://github.com/goharbor/harbor/releases) and the upgrade
guide for the target version first. Each guide states which versions it
migrates from (v2.15's covers v2.12.0 and later). Older installs have to step
through intermediate versions. The database schema, and the bundled
PostgreSQL major version (e.g. 15 → 18), are migrated automatically on start.

```bash
./scripts/harbor-docker-backup.sh                     # 1. back up (include images)

cd /var/www/docker/harbor/<domain>
(cd harbor && sudo docker compose down)               # 2. stop
mv harbor harbor-<old-version>                        # 3. keep the old installer + config for rollback

V=v2.16.0                                             # 4. new installer
curl -fLO https://github.com/goharbor/harbor/releases/download/$V/harbor-online-installer-$V.tgz
curl -fLO https://github.com/goharbor/harbor/releases/download/$V/harbor-online-installer-$V.tgz.sigstore.json
cosign verify-blob --bundle harbor-online-installer-$V.tgz.sigstore.json \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github.com/goharbor/harbor/.github/workflows/publish_release.yml@refs/tags/v.*$' \
  harbor-online-installer-$V.tgz
tar xzf harbor-online-installer-$V.tgz && rm harbor-online-installer-$V.tgz*

cp harbor-<old-version>/harbor.yml harbor/harbor.yml  # 5. migrate harbor.yml to the new version
sudo docker run -it --rm -v /:/hostfs goharbor/prepare:$V migrate -i $PWD/harbor/harbor.yml
chmod 600 harbor/harbor.yml                           #    migrate resets the mode to 644

cd harbor && sudo ./install.sh --with-trivy           # 6. install (leave out --with-trivy if disabled)
```

`migrate` keeps `http.port: 127.0.0.1:<port>` (it drops the quotes, which is
fine), the commented-out `https:` block, `external_url` and the paths. Check
them in the migrated file anyway. To roll back, run `docker compose down` in the
new `harbor/`, move `harbor-<old-version>` back, and restore the backup from
step 1.

## Useful commands

Run from `/var/www/docker/harbor/<domain>/harbor`:

```bash
sudo docker compose ps                        # status (all containers should be healthy)
sudo docker compose down                      # stop
sudo docker compose up -d                     # start
sudo tail -f ../logs/core.log                 # logs: core.log, registry.log, proxy.log, postgresql.log, ...
curl http://127.0.0.1:<port>/api/v2.0/ping    # -> Pong
```

## Troubleshooting

**`permission denied` reading `common/config/*/env`** — run `docker compose`
with `sudo` (see Reconfigure).

**`docker login` works but `push` fails with 413** — check that the Nginx vhost
is the one from `harbor-nginx.conf` (`client_max_body_size 0`, buffering off,
`X-Forwarded-Proto`).

**Harbor is reachable from outside on `<port>`** — `http.port` in `harbor.yml`
lost its `127.0.0.1:` prefix. Fix it and run `./prepare` (Reconfigure).
`docker port nginx` should print `8080/tcp -> 127.0.0.1:<port>`.

**Containers fail to start with `syslog`/`1514` errors** — every Harbor
container logs through `harbor-log` on `127.0.0.1:1514`. Something else holds the
port, or `harbor-log` wasn't up yet. Run `sudo docker compose up -d` again.

**Replication endpoints fail with decryption errors after a restore** — the
database was restored without its `secretkey`. Restore again from a snapshot
that has `secret/secret.tar.gz` (both restore options always do).
